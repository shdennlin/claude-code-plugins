# HTML Explainer — Shared Visual Spec

Shared by `digest -e html` and `/digest:explain`. Big visuals and few words up top; depth lives in collapsed sections. The reader should get the point in 3 seconds, the shape in 30, and the full story only if they expand.

## 1. Self-Containment Rules (hard constraints)

- **One file, zero network requests.** No `<script src>`, no `<link>` stylesheets, no `@import`, no remote images or fonts. No Mermaid (it needs external JS). Small images only as `data:` URIs if truly necessary.
- System font stack: `font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", "PingFang TC", "Noto Sans TC", sans-serif;` and for code `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`.
- Must render correctly opened via `file://` with the network disabled.

## 2. Skeleton

```html
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title><short title></title>
<style>/* single style block — see tokens below */</style>
</head>
<body>
  <main>
    <header class="hero">…</header>
    <section class="diagram">…</section>
    <section class="filemap">…</section>
    <details>…</details> <!-- one per deep section -->
    <footer class="meta">generated by digest · <date> · <target></footer>
  </main>
</body>
</html>
```

- Two-tier width: `<main>` at `max-width: 72rem; margin: 0 auto; padding: 1.5rem;`, prose sections capped at a readable measure (`max-width: 46rem; margin-inline: auto;`), while **visual sections break out** — diagrams, file maps, and wide tables use the full main width (`.wide { max-width: 60rem; margin-inline: auto; }`). Prose stays readable; visuals get room.
- Wide content still sits in a wrapper with `overflow-x: auto` — the body never scrolls horizontally on narrow windows.

## 3. CSS Tokens (theme via custom properties only)

Define every color as a token on `:root`; the dark override redefines **only tokens** — no other rule mentions a raw color.

```css
:root {
  --bg: #ffffff;       --fg: #1a1a1e;      --muted: #6b7280;
  --card: #f6f7f9;     --border: #e2e4e9;
  --accent: #3b6ff0;   --add: #1a9c4b;     --del: #d9483b;  --warn: #d97706;
  --radius: 10px;
}
@media (prefers-color-scheme: dark) {
  :root {
    --bg: #121316;     --fg: #e8e9ec;      --muted: #9aa1ab;
    --card: #1c1e23;   --border: #2c2f36;
    --accent: #7aa2ff; --add: #4ade80;     --del: #f87171;  --warn: #fbbf24;
  }
}
body { background: var(--bg); color: var(--fg); }
```

## 4. Hero / Conclusion Card

The first thing on the page. One `<header class="hero">` card (`background: var(--card); border: 1px solid var(--border); border-radius: var(--radius);`) containing:

- Change-type icon (emoji, large: `font-size: 2rem`) or, for explain, a topic emoji
- **Risk light**: a colored dot `●` using `--add` / `--warn` / `--del` + the risk word
- **Stat chips**: small rounded spans (`border: 1px solid var(--border); border-radius: 999px; padding: .15rem .6rem;`) — e.g. `12 files`, `8 functions`, `3 modules`
- **One-line summary** in large type (`font-size: 1.25rem; font-weight: 600`)

## 5. File Map with +/- Bars

One row per file (or per directory group), bar segments proportional to added/removed lines:

```html
<div class="filerow">
  <code>src/auth/session.ts</code>
  <span class="bar"><i class="plus" style="width:70%"></i><i class="minus" style="width:30%"></i></span>
  <span class="counts">+84 −36</span>
</div>
```

```css
.bar { display:inline-flex; width: 120px; height: 8px; border-radius: 4px; overflow: hidden; background: var(--border); }
.bar .plus  { background: var(--add); }
.bar .minus { background: var(--del); }
```

Mark risky files with a `●` in `--warn`/`--del` before the path. Group rows under directory headings when >8 files.

## 6. Inline SVG Diagram Patterns

All diagrams are inline `<svg>` using token colors (`fill="var(--card)" stroke="var(--border)"`, text `fill="var(--fg)"`, highlights `var(--accent)`), so they follow the theme automatically. Shared conventions:

- Arrowhead marker, defined once per svg:
  ```html
  <defs><marker id="arr" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7" orient="auto-start-reverse">
    <path d="M0,0 L10,5 L0,10 z" fill="var(--muted)"/></marker></defs>
  ```
- Node = `<rect rx="8">` + centered `<text>` (`text-anchor="middle"`, `font-size="13"`). Affected/highlighted node: `stroke="var(--accent)" stroke-width="2"`, others `stroke="var(--border)"`.
- Edge = `<line>` or `<path>` with `stroke="var(--muted)" marker-end="url(#arr)"`.
- Give each svg a `viewBox` and `width="100%"` with a sensible `max-width`; never fixed pixel width.

**Layer diagram** (digest): horizontal row of boxes `[API] → [Middleware] → [Service] → [DB]`; affected layers highlighted.

**Dependency / component map**: left-to-right nodes and edges; keep to ≤ 12 nodes — collapse leaf clusters into one "…N more" node.

**Call-chain / data-flow** (explain: flow, bug): a top-down or left-right chain of nodes annotated with `file:line` in `--muted` small text; the failing edge/node in `--del`.

**Why-chain** (explain: bug): three stacked boxes — symptom → proximate cause → root cause — connected by downward arrows; root cause box highlighted with `--accent`, each box's `file:line` anchor beneath.

**Evolution timeline** (explain: design rationale): horizontal axis line, dots per formative commit/PR, short hash + date above, one-phrase motivation below. ≤ 7 dots — pick formative moments, not every commit.

## 7. Collapse Pattern

Every deep section is a `<details>` (default collapsed — no `open` attribute):

```html
<details>
  <summary>📖 Code walkthrough</summary>
  <div class="body">…</div>
</details>
```

```css
details { border: 1px solid var(--border); border-radius: var(--radius); margin: .75rem 0; }
summary { cursor: pointer; padding: .7rem 1rem; font-weight: 600; }
details .body { padding: 0 1rem 1rem; }
```

**Expand/collapse-all control** — place one small button above the first `<details>`. Inline JS is allowed (the ban is on external *requests*, not scripting):

```html
<div class="ctl"><button id="xall">Expand all</button></div>
<script>
(function(){var b=document.getElementById('xall');b.addEventListener('click',function(){
  var d=document.querySelectorAll('details'),open=[].some.call(d,function(x){return!x.open});
  d.forEach(function(x){x.open=open});b.textContent=open?'Collapse all':'Expand all';});})();
</script>
```

```css
.ctl { text-align: right; margin: .75rem 0 -.25rem; }
.ctl button { background: var(--card); color: var(--muted); border: 1px solid var(--border);
  border-radius: 999px; padding: .25rem .8rem; font: inherit; font-size: .8rem; cursor: pointer; }
.ctl button:hover { color: var(--fg); border-color: var(--accent); }
```

Digest deep sections: code walkthrough, design decisions, breaking changes & migration, risks & recommendations, questions for author. Explain deep section: evidence (commands run, key commits with short hashes, code excerpts).

## 8. QA Checklist (verify before finishing)

- `grep -Ei 'https?://|<script src|<link |@import|url\([^#]' file.html` → no hits (SVG fragment refs `url(#…)` and data: URIs exempt)
- Legible in both light and dark (`prefers-color-scheme`) — every color comes from a token
- All `<details>` default collapsed; page reads coherently without expanding any
- SVGs scale on a narrow window; body never scrolls horizontally
- Hero card answers "what and how risky" without scrolling
- Expand-all button toggles every `<details>`; print/no-JS still degrades to native per-section toggles
